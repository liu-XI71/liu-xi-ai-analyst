# 求职展示与面试演示

建议职位定位：业务型 AI 数据分析师。先说明自己能定义业务问题、核对指标和提出验证方案，再用 Agent 展示如何让重复工作稳定执行。

## 五分钟演示

1. **30 秒：明确问题。** 在增长工作台选择异常诊断，说明指标是“新增用户次 7 日内至少一次回访”，使用已经完成观察的队列；精确 D7 是另一种口径。
2. **90 秒：展示证据。** 执行默认诊断，解释留存从 36.03% 到 26.85%，下降约 9.18 个百分点；结构贡献约 -6.05，组内表现约 -3.13。这些数字仅属于合成演示。点击 SQL 证据、切换渠道筛选，再执行观察结果变化。
3. **60 秒：提出行动。** 区分事实、假设和行动。说明分解不能直接证明因果，再切到随机实验复盘展示置信区间和成本护栏，讨论统计显著与业务可接受的区别。
4. **60 秒：解释工程化。** 展示 Skill 的口径与禁区、Python API、工具调用轨迹、报告导出。只有配置并实际运行过的实时结果才能用来说明真实模型能力。
5. **60 秒：展示第二场景与评测。** 切到复购 Agent，调整触达预算并查看候选/留出组；再展示评测首轮失败、修复后回归，以及尚未验证的模型指标。

## 简历表达草稿

- 独立开发增长诊断与复购运营分析工作台，将指标定义、数据窗口、分析步骤与输出规范整理为版本化业务 Skills，通过 FastAPI 串联 SQLite、Python 统计工具与 OpenAI Responses 工具调用。
- 实现成熟队列留存、渠道 × 设备对称分解、实验效果区间、时点 RFM、预算约束与随机留出建议，输出可追溯的 SQL、图表和 HTML/Markdown 报告。
- 建立包含口径歧义、不完整观察窗口、非法 SQL 和不支持指标的评测与回归测试；清楚区分静态回放、确定性业务工具与真实模型调用。

发布与真实模型验证完成后，补上实际网址、模型版本、评测日期和可复现结果。不要把合成实验效果写成公司业绩，不要把模拟客户端测试写成真实模型准确率，也不要在没有计时实验时声称“节省 80% 工时”。

## 常见追问

**为什么不直接让模型写整份报告？** 模型擅长理解和规划，但数值、样本口径和统计结论需要可复算。当前架构让模型选工具和重点，让 Python 产出经过检查的数值与证据。

**这是否支持任意数据库问数？** 当前范围是两个固定业务域和已开放表。可扩展路径是接入企业数据字典、语义指标层、用户权限与专门的 SQL 评测，不应把受限演示说成任意企业数据库平台。

**为什么要把静态和实时分开？** 招聘方可以无需密钥快速看懂案例；实时服务则证明模型与后端确实连通。两者解决不同展示需求，界面应明确标识。

**如何证明 Agent 比单个提示词更可靠？** 展示同一指标跨问题的口径一致性、工具参数校验、拒绝不支持指标、只读 SQL 限制、失败记录，以及独立 SQL 对数。可靠性应由实际评测支持。
