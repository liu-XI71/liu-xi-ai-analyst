# 业务讲解与复现路线

## 路线一：新用户留存下降

打开增长工作台，选择完整数据场景。先看业务摘要与决策，再展开精确 D7 的分子分母、成熟窗口和质量水位。检查渠道×端联合分解是否与总体变化闭合，随后查看注册后24小时有序漏斗与版本关联。

下载报告，选择一条 SQL 证据重放。版本与留存同期变化支持继续排查，但不能直接证明因果。后续行动应是核对错误日志、提出候选修复和预注册实验。

## 路线二：数据延迟与恢复

切换延迟快照，观察受影响指标被阻断，原始数据质量证据指出缺失批次。切换恢复快照，确认同一 cohort 重新计算。对照监控视图的数据告警恢复与业务告警持续，解释两者为什么不能混为一谈。

## 路线三：实验的收益与体验代价

先查看健康实验的预注册窗口、分配、样本量规划和效应区间，再切换负反馈围栏场景。负反馈围栏未通过时，主指标提升也不能满足发布条件。随后查看 SRM、未成熟和样本不足，区分无效数据与有效但不足的证据。

## 路线四：复购预算

查看截止日前 RFM 和匿名候选，核对预算、触达单价、整数人数与留出组。解释正向订单金额、利润、完整 LTV 与干预增量的区别。计划不代表已经完成触达或获得收益。

## 方法问题

- 精确D7与次1—7日回访为何不同？
- 注册23:59的用户，其24小时激活窗口与D1自然日如何界定？
- 结构变化和分层内表现如何分解，为什么不构成因果证明？
- 为什么使用原始分配组而非只分析暴露用户？
- 为什么围栏未显著恶化不等于通过非劣检验？
- 数据回填后业务指标仍下降时，告警如何处理？
- 技术完成率、用户自评与经核验的任务成功率有什么区别？
- 模型在哪些任务上有额外价值，如何与确定性工具比较？
