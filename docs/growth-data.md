# 增长数据与分析实现

本项目独立生成演示数据，不下载或修改旧作品集数据，也不把个人经历中的业务结果作为合成数据目标。`app/domains/growth.py` 使用 Python 标准库，公开 `metadata()`、`build_database(path)`、`analyze(request, path)` 三个接口。

## 可复现数据

- 固定随机种子：71。注册日期 2026-07-06—2026-09-06；每天 145—175 个用户。
- 数据快照：2026-09-06。成熟注册队列最晚 2026-08-30。
- 四个渠道、三个设备；2026-08-24 起获客结构改变，付费搜索 Android 的留存概率也改变。这些是生成器中的教学机制，分析输出不会将模拟真相冒充从观察数据识别出的因果关系。
- 2026-08-17—30 注册用户按用户独立随机 1:1 分为处理组和对照组。生成器设置处理效应，最终展示值仍由实际随机样本计算。
- 用户表 `growth_users`：用户 ID、注册日、渠道、设备、实验组、激励成本、7 日收入。活动表 `growth_activity`：用户与自然日唯一。注册当日为每个用户生成活动，但次 7 日内留存 SQL 显式排除注册日。
- 不写入快照后的活动。未成熟用户不纳入完整 7 日窗口，无论其是否已有活动。
- 重复构建同版本数据为幂等操作；仅管理 `growth_*` 表，保留其他领域表。

## 口径与算法

指标合同详见 [业务 Skill 指标字典](../skills/growth-diagnosis/references/metric-dictionary.md)。所有核心查询均使用 SQLite 绑定参数；渠道、设备只能从批准的字段和枚举选择。分析连接采用 `mode=ro` 和 `PRAGMA query_only`。这些约束用于固定领域查询，不等价于通用 SQL 沙箱。

`diagnose` 和 `report` 从两期成熟队列计算人数和次 7 日内留存；对渠道 × 设备的联合分层计算对称结构/表现分解，两项之和精确还原总体变化。图表包括每日队列、两类贡献、渠道及设备比较。单维图仅用于核查，不能相加。

`experiment` 按原始分配组 ITT 分析，计算未合并标准误的正态近似绝对提升置信区间、合并零假设标准误的双侧两比例 z 检验，以及 1:1 分配的卡方 SRM 检验。每组 200 人、各组至少 10 个留存和未留存样本是演示中的最低检查，不是预注册样本量或功效计算。CI 下界 >0、点估计 ≥1.5pp、每用户增量激励成本 ≤0.35 元、SRM p≥0.01 和样本门槛同时通过，才标记可进入小流量验证。

上述统计与分解代码依据公开数学定义独立实现；未复制旧仓库函数或引入旧仓库依赖。SRM 的通过不证明随机化正确；筛选后的子组是探索性结果。7 日收入只作描述性比较，不计算完整 ROI 或利润。

## 运行与验收

安装项目依赖后，在仓库根目录执行：

```bash
python -m unittest discover -s tests -p 'test_growth.py' -v
```

12 项行为测试覆盖：数据复现和幂等、独立事件级留存核验、对称分解可加性与时间反转、新增分层约定、筛选有效性和参数绑定、无效输入、未成熟/超范围日期、空数据、实验统计核对、无随机组、样本门槛、全部证据 SQL 回放及 JSON 数值有效性。

返回的每条事实引用 evidence ID，每条 evidence 包含 SQL、参数、行结果、合成数据声明和指标版本；报告导出可复用本次结果。没有真实模型凭据时，领域计算仍可被确定性演示调用，但不得将其标为模型端到端评测结果。

默认合成结果（v1.0）：2026-08-24—30 留存 294/1095 = 26.85%；2026-08-17—23 为 419/1163 = 36.03%；总体 -9.18pp，结构约 -6.05pp、表现约 -3.13pp。完整随机实验处理组 390/1124、对照组 323/1134，绝对提升约 +6.21pp，95% CI 约 [2.39,10.04]pp。这些数字仅用于复现核对。
