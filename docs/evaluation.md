# 评测范围、结果与复现

这份报告区分三个问题：有限任务路由是否正确、确定性计算是否符合业务口径、信息不足或不支持时是否采取正确行为。它不把无模型的演示结果当成大模型准确率。

## 样本与执行边界

- 主验收集：[60 题 JSON](../evals/cases.json)，预先分为 40 个 `development` 与 20 个 `heldout`；两部分各覆盖增长与复购。
- 新增审计：[10 题 JSON](../evals/audit-cases.json)，主集首次失败修复后另行编写，首次执行前没有用于修改业务实现。
- 问题类别：正常任务、口径歧义、输入澄清、无数据、未成熟队列、非法日期和写入拒绝。正常题覆盖诊断、实验、报告、分群、日期对比及筛选组合。
- 实际执行路径为 Pydantic `AnalysisRequest` 校验 → 应用 `app.engine.analyze_domain` → 真实 SQLite 查询和业务计算；实时模式调用 `app.live_agent.execute`。
- `demo` 使用有限关键词路由，日期、筛选与预算由结构化字段传入。本次不验证自由自然语言的日期/筛选抽取，也不验证通用 Text-to-SQL。
- 本脚本不包含 HTTP 限流、浏览器交互、远端网络、真实模型时延和报告下载的端到端验收。那些由应用测试和人工演示另行验证。

所有数据都是项目自建固定种子合成数据。样本集公开且规模有限，不代表真实企业提问分布、招聘方业务环境或生产错误率。

## 数值基准为什么独立

评测脚本不导入领域 SQL 常量或统计函数，不从一次业务输出提取数值再当标准答案。

1. **增长留存**：独立读取用户表与活动明细，在 Python 逐用户去重、按真实日期差判断 D1—D7 活动，再计算成熟人数和留存。验证本期、对比期、绝对变化，以及结构贡献 + 表现贡献 = 总体变化。
2. **随机实验**：从同一份独立事件聚合按随机组统计分母与留存，按公开数学公式计算差值、正态近似 95% CI 与 1:1 SRM。验证统计输出与分组样本对应；不把模拟处理效应设定值当成观察结果。
3. **复购队列**：独立读取原始正向订单，识别全历史首次观察购买日，逐订单判断 D1—D7/D1—D30，以及 D0—D29 的交易额。分别构造完整观察分母；没有成熟用户时标准答案是 null，不是 0。
4. **候选与预算**：独立按截止日前原始订单重建 R/F/M 与分群，验证候选资格、客户唯一性、截止日特征、预算上限、留出人数与处理成本。复杂候选排序未在本评测脚本另写一份同构实现；验证范围明确限于这些不变量。
5. **输出合同**：验证必需字段、可解析图表、JSON 有限数值、事实引用存在的证据、澄清不输出经营 KPI。证据引用通过不等价于文本每个数字已被语义核验。

各指标按样本计数：一题中任一相同类别检查失败，该题在该类别即失败。没有该类检查的题不进入分母。例如无事实的澄清结果不会增加“事实证据引用”通过数。

## 保留失败历史

| 阶段 | 首次结果 | 文件 | 解释 |
|---|---:|---|---|
| 主验收集首次运行 | 56/60 | [first-run.json](../evals/first-run.json) | development 40/40；heldout 16/20 |
| 主验收集修复后回归 | 60/60 | [results.json](../evals/results.json) | 属于已暴露回归集，不能继续称盲测 |
| 新增 10 题首次审计 | 6/10 | [audit-first-run.json](../evals/audit-first-run.json) | 新的表述和边界暴露 4 个错误，保留原始失败 |
| 审计集修复后回归 | 10/10 | [audit-results.json](../evals/audit-results.json) | 同一预写题集回归，不再称未见评估 |

主集首次失败：`D7` 紧邻中文时未被单词边界正则识别；请求净利润、完整 ROI、净 LTV 时被默认留存/复购分析替代。修复的是业务输入路由，不修改用例标准来提高分数。

新增审计首次失败：增长 D30 留存、汉字“第七天”、复购精确 D30 被误路由到窗口指标；小写 `delete from` 请求未产生只读澄清。没有实际执行写入，失败属于请求语义与拒绝呈现。新增审计一旦用于修复，也成为回归集；修复后结果应单独保存，不覆盖首次记录。

当前主集的分项结果：有限任务路由 27/27；独立数值及不变量 28/28；业务状态 60/60；有事实输出的证据引用 29/29；异常与边界行为 36/36。各项分母不同，因为只统计适用样本。新增审计最终 10/10，其中包括正常数据计算、空候选以及新的口径与写入请求表述。

后续真实泛化评估需要重新采集独立问题和业务数据；不能继续在已公开题集上调参后声称“未见问题准确率 100%”。主集及审计结果都记录用例文件 SHA-256，便于核对测试输入是否变化。

## 真实模型状态

[live-results.json](../evals/live-results.json) 记录了无 Key 时的实际调用入口行为：`status=not_run`、`live_status=not_run`、执行样本数 0。没有把 demo 结果复制为模型测试结果。此状态不证明模型工具规划、SQL 生成、实际计费、稳定性或真实用户提效。

安全配置 `OPENAI_API_KEY` 后再运行实时评测。模型评测会真实消耗 API token；默认 main 集是 60 题，可先用 `--limit 3` 验证链路，再冻结模型与提示词版本执行完整集和重复运行。输出保留实际 `model_run`、token 数、调用轮次、耗时以及失败；不得只报告成功的样本。

## 复现命令

```bash
# 安装仓库依赖后，从仓库根目录执行
python scripts/evaluate.py

# 新增审计；不覆盖首次结果
python scripts/evaluate.py --suite audit

# 实时模型冒烟：没有 Key 时明确 not_run，退出码 2
python scripts/evaluate.py --mode live --limit 3

# 完整实时模型集，建议另存按模型/日期命名的结果
python scripts/evaluate.py --mode live --repeat 3 --output evals/live-repeated-results.json
```

退出码：0 表示当前所选样本检查均通过，1 表示至少一个失败，2 表示无法开始实时模型评测或参数错误。结果会写出适用样本数、失败检查、实际/期望值与耗时；本机引擎耗时不能当作云时延或人工节省时间。

## 还需用真实工作测量的指标

尚未测量：业务人员完成同等交付物的人工分钟数、原有确定性工作台与 AI 模式的额外差异、人工修订率、真实模型重复成功率、模型费用以及真实业务收益。没有这些测量，作品集不应写“节省 80% 工时”“大模型准确率 100%”或“推动真实增长”。
