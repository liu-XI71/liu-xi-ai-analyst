# 新用户承接实验：设计、评审与决策

本模块评估一个具体业务决策：新用户承接改版带来的精确 D7 留存提升，是否足以补偿体验风险，并具备进入人工灰度评审的证据。所有案例由固定种子 7109 的用户级合成记录生成，数值从实际记录重新计算，不代表企业经营收益。

## 分析合同

- 随机单位：稳定匿名用户 ID，每名用户在注册成功时分配一次。分析按初始分配组进行 ITT，包括未看到实验界面的用户。
- 主指标：精确 D7 留存。分子为注册后第 7 个自然日有至少一次 `qualified_activity` 的原始分配用户；分母为完整入组窗口内全部合格分配用户。
- 时间：`Asia/Shanghai`，本地时间戳。存储格式固定为有效公历 `YYYY-MM-DD HH:MM:SS`，使用空格分隔、秒精度、无时区后缀；注册表日期固定为 `YYYY-MM-DD`。D7 区间为 `[注册日+7日 00:00, 注册日+8日 00:00)`；自然日和满 168 小时不是同一口径。
- 围栏：注册后 `[0,24h)` 内至少一次 `negative_feedback` 的用户比例。它与 D7 使用同一分配人群，观察窗口独立。
- 水位：`snapshot_date` 是完整到数的最后自然日。截止时刻为次日 00:00，事件时间和入库时间均须早于该时刻。
- 成熟：评审完整固定窗口。任一分配用户的 D7 尚未完整结束时，等待成熟；不把未观测结果填 0，也不剔除该用户后宣称总体结论。
- 业务条件：主要效应区间下界至少达到预注册最低业务提升。仅点估计越过门槛，不足以进入灰度评审。

精确 D7 不等于次日到第七日任意回访。生成器有额外 D1 活跃事件，测试通过独立事件集合确认这些事件不会误计入 D7。

规范时间是评审前提，覆盖注册、分配、暴露、事件发生、入库、采集水位和配置变更。ISO `T` 分隔符、仅日期、小数秒、`Z` 或偏移量后缀、混合格式、`24:00:00` 及不存在的公历日期均会触发 `invalid_data`，屏蔽效应与围栏结论。SQL 使用规范时间的文本顺序计算区间，因此“解析器可以读懂”不足以通过质量检查；质量证据包含格式检查及零秒日期运算后的精确回比较，可直接在 SQLite 重放。

接入层应先按来源时区解析，再显式转换为 `Asia/Shanghai`，按约定的秒精度规范化并保留转换记录。评审模块不会自行猜测时区、截断精度或丢弃不合格记录。将同一时刻由空格改写为 `T` 不会被解释为负反馈减少；数据须修复后才能重新评审。排他边界保持不变：D7 末端、24 小时末端及快照次日 00:00 均不计入对应已完成窗口。注册表也须允许表示完整 D7 和快照的排他截止时刻。

## 原始数据与可追溯性

| 表 | 职责 | 主要核查 |
|---|---|---|
| `experiment_registry` | 实验分配比例、入组/观察范围、基线、MDE、功效、围栏和源端人数清单 | 参数有效，窗口冻结，来源人数可对账 |
| `experiment_assignments` | 用户注册与原始分配记录 | 重复身份、串组、错误资格和分配时间 |
| `experiment_exposures` | 实际界面暴露日志 | 暴露组与分配组一致；不作为 ITT 的纳入条件 |
| `experiment_outcomes` | 活跃与负反馈事件 | 来源身份、事件版本、时间、入库水位；用户内去重 |
| `experiment_coverage` | 每名分配用户的采集水位和完整标记 | 缺清单、未完整、与快照不一致 |
| `experiment_changelog` | 配置变更轨迹 | 入组或观察期内实质变更，冻结版本不符 |

一次报告在同一个 SQLite 只读事务内查询，避免多次查询读取不同快照。每份证据保存 SQL、绑定参数、结果行、口径版本和来源。统计输入取自证据结果；图表复用这些结果，不另行生成数字。

采集完整性的结论限于当前来源清单与合同。即使条数一致，也不能证明真实上游不存在未记录的人群或事件。接入外部数据时需提供独立源端清单、实验分配审计和埋点校验。

## 样本规划

默认设计参数是本项目预注册的演示约定，不是所有增长实验的通用阈值：

| 参数 | 默认值 |
|---|---:|
| D7 基线 | 28% |
| 主要指标 MDE | 2.5 个百分点 |
| 主要指标双侧 alpha | 0.05 |
| 设计功效 | 0.80 |
| 最低业务提升 | 区间下界至少 +1.0 个百分点 |
| 负反馈基线 | 4% |
| 负反馈非劣界值 | +1.5 个百分点 |
| 围栏单侧 alpha | 0.025 |
| SRM alpha | 0.001 |

设处理/对照样本比为 `r`，采用 Cohen h 的正态近似规划主要指标：

```text
h  = 2 asin(sqrt(p0 + MDE)) − 2 asin(sqrt(p0))
nC = ceil[(1 + 1/r) × (z(1−alpha/2) + z(power))² / h²]
nT = ceil(r × nC)
```

效应量和不等流量功效参数与 [statsmodels 的比例效应量定义](https://www.statsmodels.org/stable/generated/statsmodels.stats.proportion.proportion_effectsize.html)及 [NormalIndPower 设计参数](https://www.statsmodels.org/stable/generated/statsmodels.stats.power.NormalIndPower.solve_power.html)一致；实现使用 Python 标准库，未引入运行依赖。

围栏采用假设真实差异为零的非劣设计近似：

```text
nC_NI = ceil[p(1−p) × (1 + 1/r)
             × (z(1−alpha_NI) + z(power))² / margin²]
nT_NI = ceil(r × nC_NI)
```

最终取主要指标和围栏各自所需样本量的较大值。默认 1:1 设计，主要指标每组 5,196 人，围栏每组 2,680 人，因此最终每组至少 5,196 人。更小 MDE、更高功效或不等流量会改变需求；系统不使用固定“每组 200 人”的通用放量规则。

这是两项各自的设计功效，不保证“所有条件同时通过”的概率达到 80%。主要指标的设计检验原假设是差异为零，也不保证“区间下界达到 +1pp”具有相同功效。历史基线不确定、聚类干预、稀有事件或复杂流量分配时，需要重新设计；不会以事后 observed power 替代区间分析。

## 效应与不确定性

绝对提升为 `pT − pC`，对外显示百分点；相对提升为 `(pT − pC) / pC`。若对照率为零，相对提升返回 `null`，不能显示为 0% 或无穷大。

主要区间使用两组独立 Wilson 区间组合的 Newcombe 方法，避免极端比例下普通 Wald 区间退化为零宽度；方法来源见 [Newcombe 1998 原论文](https://pubmed.ncbi.nlm.nih.gov/9595617/)。双侧 pooled z 的 p 值用于辅助解释，与 Newcombe 区间不是同一个检验的精确反演；最终规则使用预注册区间门槛，不依据两者临界附近的微小差异择优。

负反馈越低越好。非劣原假设为 `pT−pC ≥ margin`。通过条件为单侧 97.5% 置信上界严格小于 +1.5pp；当前实现取相应双侧 95% Newcombe 区间的上界。若区间下界已达到或超过该界值，建议停止或调整；若界值位于区间内部，证据仍不充分，不能把“不显著”改写为“安全”。

## 分配与数据门槛

SRM 使用预注册分配比例的卡方检验，1 个自由度。预期人数每组至少为 5 才使用该近似。通过只表示没有达到当前阈值的比例异常，不能替代其它质量检查。比例失衡可能来自分配、日志、身份或错误筛选，发现后暂停效应解释。[Microsoft 的 SRM 实践](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/)解释了这类问题为什么可能逆转业务结论。

本项目阈值 0.001 是预设方法参数，没有复制某个平台的阈值并将其视为行业标准。预注册 30:70 的实验使用 30:70 检验，不能拿 1:1 误报异常。效果比较使用各组比例，而不是直接比较留存人数。

评审不接受任意渠道、设备或暴露人群筛选，也不接受缩短固定入组日期来寻求显著。探索性子组需要另外报告多重比较、选择机制和预注册状态。

## 决策状态

| 决策 | 含义 | 后续动作 |
|---|---|---|
| `invalid_data` 数据需修复 | 来源、身份、事件、配置或 SRM 前提失败 | 屏蔽效应结论，修复并保留回填记录 |
| `waiting_for_maturity` 等待成熟 | 固定观察窗口不完整 | 等待最后队列成熟和采集完成 |
| `insufficient_evidence` 证据不足 | 样本不足、业务门槛不确定，或不能证明围栏非劣 | 保留区间和不确定性，另行登记后续方案 |
| `stop_or_adjust` 建议停止或调整 | 主指标区间整体为负，或围栏恶化已越界 | 检查机制、调整方案，不扩大发布 |
| `review_for_gradual_rollout` 满足预设条件 | 质量、成熟、样本、业务效应和围栏均通过 | 人工复核成本、适用人群、灰度和回滚条件 |

所有状态都不会直接执行发布、营销触达或数据库业务写入。“停止或调整”是评审建议，固定窗口内若观察到风险，实际业务应由预设安全流程处理；不能借此按每日统计显著性反复提前宣布实验成功。

长期 Holdout 可以研究累计和组合效应，适用条件取决于问题与实验设计，并非所有短期有效 A/B 的统一上线前提。[Statsig Holdout 文档](https://docs.statsig.com/experiments/holdouts-introduction)说明了其用于保留总体对照与长期评估的定位。

## 八个可运行案例

| 场景 | 记录中设置的条件 | 评审关注点 |
|---|---|---|
| `healthy_gain` | 完整同版本、有效随机分配、正向主要结果 | 完整链路与灰度评审条件 |
| `srm` | 实际分配与预注册比例不一致 | 暂停效应结论 |
| `guardrail` | 留存增加但负反馈同时上升 | 业务取舍与围栏约束 |
| `immature` | 最近注册队列尚未完成 D7 | 未成熟不是失败 |
| `underpowered` | 完整有效数据但总样本不足 | 有效数据不等于证据充分 |
| `unequal_allocation` | 正确预注册的 30:70 分配 | 比例与功效按真实配置计算 |
| `config_change` | 实验运行中修改配置 | 不把不同策略版本混作同一处理 |
| `data_gap` | 部分用户缺少采集覆盖清单 | 缺数与真实行为变化分开 |

决策不读取场景标签来挑选答案。测试会修复异常场景的数据，也会破坏健康场景的数据，验证同一标签的决策随记录变化。

## 复现

```bash
.venv/bin/python -m unittest tests.test_experiments tests.test_experiment_boundaries -v
.venv/bin/python skills/experiment-review/scripts/review_experiment.py \
  --db var/experiments.sqlite --init --scenario guardrail
```

调用业务模块：

```python
from pathlib import Path
from app.domains import experiments

path = Path("var/experiments.sqlite")
experiments.build_database(path)
result = experiments.analyze({
    "domain": "experiments",
    "task": "report",
    "filters": {"scenario": "healthy_gain"},
}, path)
```

公开测试验证确定性业务行为、原始事件复算和证据重放。它们不衡量模型理解任意问题的准确率，也不构成真实模型盲测。
